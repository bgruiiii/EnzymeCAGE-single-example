## 3. Working Hypothesis

R1 shows strong EC-family / EC-functional alignment but low row-level /
UniProt-level R→E discrimination, likely because two effects interacted:

1. H1: hard-negative mining is too coarse.
   - The training code encodes EC labels by first digit only.
   - In 4096-size batches, this creates hundreds of same-EC-1-digit negatives
     per anchor.
   - The current `hard_neg_weight = 2.0` likely over-penalizes broad same-class
     enzymes that may be biologically related.

2. H3: Stage 1 is undertrained at full-data scale.
   - Stage 1 directly trains the pairwise `R↔E` and `E↔M` objectives.
   - Full-data complexity increased far more than the number of Stage 1
     optimization steps.
   - Fine-grained R→E discrimination may not have converged before entering
     later stages.

Therefore R2 should reduce coarse hard-negative pressure and give Stage 1 more
optimization time, while keeping Stage 2 unchanged to preserve attribution.

Use the full ESM-C enzyme feature mode.

Teacher revision note added after this draft:

```text
Remove EC encoding as an R2 training change. With hard_neg_weight = 1.0, the
same-EC weighting term degenerates to 1.0, so changing EC encoding would be a
dead-code/confounding training variable for this R2 run.
```

Interpretation of `hard_neg_weight = 1.0`:

- This disables extra same-EC hard-negative upweighting.
- Same-EC examples remain ordinary InfoNCE negatives unless otherwise masked.
- This is the least invasive way to remove the suspected coarse EC-1 hard
  negative pressure.

Superseded interpretation of EC first-two-digit encoding:

- If hard-negative weighting is later re-enabled, the label granularity will be
  less coarse than first-digit EC.
- For this R2 run with `hard_neg_weight = 1.0`, first-two-digit EC encoding is
  still useful for diagnostics, metadata consistency, and future ablations.


### 6.2 EC Encoding Change

Current behavior:

- EC labels for hard-negative logic are effectively first-digit EC classes.

Required behavior:

- parse `metadata["ec_number"]` into first two EC digits when available, for
  example:
  - `1.1.1.1 -> 1.1`
  - `2.7.11.1 -> 2.7`
- if fewer than two EC digits exist, assign an unknown/sentinel label.
- avoid collapsing all unknowns into a biologically meaningful EC class.

Implementation boundary:

- This is a training-data label parsing change for `ec_ids`, not a loader data
  source change.
- It should not change reaction, enzyme, substrate, or microbe feature tensors.

### 6.3 Stage-End Checkpoint Saving

R1 did not save stage-end checkpoints, so per-stage attribution was impossible.

R2 must save:

```text

```

or equivalent stage-end artifacts that contain:

- model state
- FBA surrogate state if used
- Config snapshot
- stage index
- epoch index
- training history up to that point

This is an artifact/diagnostic requirement. It should not change training
updates.

### 6.4 Metrics After R2

R2 reporting must include the original row-level metrics and the grouped
metrics:

- row-level R→E top-1/top-5/top-10/MRR
- UniProt-grouped R→E top-1/top-5/top-10/MRR
- EC-2-digit-grouped R→E top-1/top-5/top-10/MRR
- E→M and S→M original metrics
- grouped E→M and S→M if feasible and clearly defined
- effective-rank summary
- per-stage R→E evaluation if stage checkpoints are evaluable

Grouped metrics should be primary interpretation metrics. Row-level metrics
remain the continuity baseline against R1.

## 7. Expected Outcomes

Primary expected improvement:

- UniProt-grouped R→E MRR should improve above R1 `0.0581`.
- Row-level R→E MRR may improve, but row-level strictness remains harsh.

Secondary expected behavior:

- EC-2-digit grouped R→E MRR should remain high. A large drop from `0.9340`
  would indicate that exact alignment improvements damaged coarse biological
  structure.
- E→M MRR should not collapse. R1 ESM-C E→M MRR was `0.609`.
- S→M MRR should be monitored because ESM-C R1 was slightly lower than GVP on
  this metric.

Failure modes to watch:

- R→E exact metrics do not improve despite longer Stage 1.
- EC-2 grouped metrics drop substantially.
- E→M alignment deteriorates after the EC/hard-negative change.
- effective ranks collapse or become less balanced.
